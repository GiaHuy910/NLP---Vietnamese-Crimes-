# Part 2: Trigger, Argument, and Relation

This directory contains the Part 2 evaluator, rule-based baseline, and PhoBERT models. It uses a
schema with 8 event types and 10 roles (see `docs/annotation_guidelines.md`). The evaluator and
baseline use only the Python standard library; model training and inference require `torch`,
`transformers`, and `underthesea` (included in `requirements-ner.txt`).

## Files

- `schema.py`: 8 event types, 10 roles, and the entity labels allowed for each role.
- `data.py`: reads and writes `.jsonl`, validates offsets and relations, and converts sentences to span-based events.
- `metrics.py`: evaluation metrics.
- `baseline.py`: rule-based baseline (trigger keywords and role-linking rules).
- `model.py`: PhoBERT models (BIO trigger tagging and role classification for each trigger–entity pair).
- `evaluate.py`: evaluation command-line interface.

## Data

Use the three gold files `datasets/train.jsonl`, `val.jsonl`, and `test.jsonl`, generated by
`data_pipeline/step7_export_dataset.py`. Prediction files must use the same format: one sentence per
line with `ann_id`, `sentence`, `entities`, `triggers`, and `relations`. Span IDs do not need to
match the gold IDs because evaluation uses character offsets.

## Metrics

All metrics use exact character-offset matching and micro-averaged Precision, Recall, and F1.

| Metric | A prediction is correct when |
|---|---|
| Trigger Identification | The trigger offsets match. |
| **Trigger F1** | The trigger offsets and event type match. |
| **Argument F1** | The trigger (offsets + type) and linked entity offsets match. |
| **Relation F1** | Argument F1 conditions match, including the role. |
| **Event Exact Match** | The trigger is correct and all arguments (offsets + roles) exactly match gold. |

The report also includes Trigger F1 by event type and Relation F1 by role.

## Run (from the `server/` directory)

```powershell
# Evaluate the rule-based baseline on test.
python -m src.event_pipeline.evaluate --gold datasets/test.jsonl --baseline --errors 30

# Save predictions and evaluation results.
python -m src.event_pipeline.evaluate --gold datasets/test.jsonl --baseline `
  --save-pred datasets/processed/test_baseline_pred.jsonl `
  --save-json datasets/processed/test_baseline_eval.json

# Evaluate a model prediction file.
python -m src.event_pipeline.evaluate --gold datasets/test.jsonl --pred datasets/processed/test_pred.jsonl

# Run the metric tests.

```

## Rule-based baseline results

Entities are taken from gold to evaluate Part 2 independently of NER errors. Rules are tuned only
on train and validation; test is run once for final reporting.

| Split | Trigger F1 | Argument F1 | Relation F1 | Event Exact Match |
|---|---|---|---|---|
| train (301 sentences) | 0.877 | 0.711 | 0.696 | 0.332 |
| validation (150 sentences) | 0.756 | 0.621 | 0.594 | 0.347 |
| **test (150 sentences)** | **0.697** | **0.629** | **0.589** | **0.275** |

Validation and test scores are similar, suggesting that the rules were not tuned specifically to test.

## PhoBERT models

1. **Trigger**: BIO-tag segmented words (segmented with underthesea) for 8 event types. The majority
   `O` label receives a lower loss weight (`--o-weight 0.3`).
2. **Argument**: for each trigger–entity pair in a sentence, insert `<t> </t>` around the trigger,
   `<e> </e>` around the entity, and prepend event-type and entity-type tokens. Classify the pair as
   one of 10 roles or `NONE`. At inference time, only roles allowed for the entity label are considered
   (the `ROLE_TYPES` mapping).
3. Select checkpoints by validation F1: Trigger F1 for the trigger model and Relation F1 with gold
   triggers for the argument model. Test data is not used during training.

```powershell
# Train both models (recommended: GPU such as a Colab T4; approximately 10–15 minutes).
python -m src.event_pipeline.model train --task all --epochs 15

# Predict on test using gold entities, then evaluate.
python -m src.event_pipeline.model predict --split test
python -m src.event_pipeline.evaluate --gold datasets/test.jsonl --pred datasets/processed/test_event_pred.jsonl
```

Models are saved under `server/models/event_trigger/` and `server/models/event_argument/` and are
not committed to Git. Training history (loss and validation F1 per epoch) is saved in each
directory's `train_history.json`.

## Baseline behavior

- **Triggers**: match keywords from `TRIGGER_LEXICON`, preferring longer phrases. A `MA_TUY` trigger
  requires a nearby drug mention; "weak" verbs such as deliver, hide, or store count only when a drug
  is mentioned immediately afterward. "Restrain, arrest" and a sequence of fraud tactics (e.g.
  impersonating someone and making a false claim) are treated as one event. Exclude non-trigger uses
  (e.g. `bắt đầu`, `trại tạm giam`, `kẻ trộm`, `nhóm cướp`), keywords following unrealized-event cues
  (e.g. `ý định`, `để`, `sẽ`, `không`, `đề nghị`), and keywords inside crime names or organization
  names. Repeated mentions of "khởi tố" keep only the first occurrence.
- **Roles**: consider only entities in the same clause as the trigger:
  - CRIME maps to TOI_DANH; TIME maps to THOI_GIAN (or MUC_AN for a sentence length with an XET_XU trigger).
  - LOCATION maps to DIA_DIEM unless it describes a hometown or residence (e.g. `quê`, `trú`, `ngụ`,
    `SN 1990, ở...`), including multi-level addresses in parentheses.
  - Do not link TIME before `cho biết` or `thông tin` when it refers to the reporting date.
  - The nearest preceding ORGANIZATION is CO_QUAN for procedural events.
  - For procedural events, a PERSON after the trigger is DOI_TUONG. For crime events, a PERSON before
    the trigger is DOI_TUONG and a PERSON after it is NAN_NHAN.
  - Link DRUG, PRODUCT, and MONEY according to event type as TANG_VAT, TAI_SAN, or HUNG_KHI.
